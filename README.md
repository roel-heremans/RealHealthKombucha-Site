# RealHealthKombucha-Site

Static, bilingual (English / European Portuguese) site for realhealthkombucha.com, generated with Jinja2 (no Framer).

## Setup
    python3 -m venv .venv && . .venv/bin/activate
    pip install -r requirements.txt

## Build, test, preview
    ./build-output.sh                                  # writes output/
    pytest -q                                          # must be all green before a push
    python -m http.server -d output 8000               # http://localhost:8000/

## Page structure
Seven pages, each in English (`/…`) and Portuguese (`/pt/…`):

| Page | English | Portuguese | Template |
|---|---|---|---|
| Home | `/` | `/pt/` | `home.html.j2` |
| For restaurants | `/for-restaurants/` | `/pt/para-restaurantes/` | `restaurants.html.j2` |
| Flavours | `/flavours/` | `/pt/sabores/` | `flavours.html.j2` |
| Our story | `/our-story/` | `/pt/a-nossa-historia/` | `story.html.j2` |
| Gut health | `/gut-health/` | `/pt/saude-intestinal/` | `gut-health.html.j2` |
| Order | `/order/` | `/pt/encomendar/` | `order.html.j2` |
| Contact | `/contact/` | `/pt/contacto/` | `contact.html.j2` |

Old URLs still work through small redirect pages: `/shop/` → Order, `/reseller/` → For restaurants, `/about/` → Our story, `/gut-health-101/` → Gut health. The language switch in the header always goes to the same page in the other language. Shared parts (header, footer, profit tables, partners list…) are in `src/templates/partials/`; styles in `assets/css/styles.css`; the only script is `assets/js/site.js` (phone menu, fade-in).

## Changing content (both languages)
All copy, prices, links and contact details live in `src/content.py`; templates in `src/templates/`.

- Every visible text is a pair `{"en": "...", "pt": "..."}`. **Always edit both.** A test fails if one side is missing or empty, so an English-only text can never slip onto a Portuguese page.
- Pages are listed in `CONTENT["pages"]` (id, template, EN/PT slug, title, nav label); old URLs in `CONTENT["redirects"]`.
- Prices and the restaurant tables (`prices`, `restaurants.glass_rows`, `restaurants.bottle_rows`, the typical month) must match the spec; tests check every figure on both the EN and the PT page. The "72%" and "2.5×" highlights are tied to the glass table by a test.
- Numbers and euros are formatted per language by the `eur` and `num` filters (`€8.00` / `8,00 €`).

After a change: `./build-output.sh && pytest -q`.

## Images
`assets/img/` is generated by `tools/prepare_images.py` from Roel's source folders. It needs the **Kombucha repo checked out next to this one** (`~/Documents/PersonalRepos/Kombucha`, read only) and ImageMagick:

    python tools/prepare_images.py

The script's lists (`PHOTOS`, `LABELS`, `OG`) say which source photo becomes which file, with crop and size. To add or drop a photo, edit `PHOTOS` and run it again; a test fails if an image in `assets/img/` is not used by any page, and another if `PHOTOS` and `assets/img/photos/` disagree.

### Orders-app screens
The phone screens on the restaurant page (`assets/img/app/`) are real screenshots of the orders app, rendered offline with sample data (no real customers, no Firebase):

    python3 tools/app_screens/make_screens.py --app ~/Documents/PersonalRepos/kombucha-orders-app

Use the system `python3` (it needs Pillow) and google-chrome. See the script's docstring for details.

## Deploy (phase 1: GitHub Pages test site)
Pushing to `main` runs `.github/workflows/deploy.yml`: install, `pytest -q` (failing tests block the deploy), build, publish `output/` to
https://roel-heremans.github.io/RealHealthKombucha-Site/ . While `CONTENT["preview"]` is True every page carries a `noindex` meta tag (this is what keeps the test site out of search engines). The generated `robots.txt` disallows all, but on a project Pages site it is served under `/RealHealthKombucha-Site/robots.txt`, which crawlers do not read, so it gives no protection here; it only matters once the site is on its own domain.

## Deploy (phase 2: live site on STRATO)
The same workflow has a second job, `strato`, that builds with `SITE_ENV=production` (no `noindex`, robots.txt allows all and lists the sitemap) and uploads `output/` over SFTP with `tools/deploy_strato.py`. It only runs when the repository variable `STRATO_DEPLOY` is `true`.

Settings → Secrets and variables → Actions:
- secrets `STRATO_HOST`, `STRATO_USER`, `STRATO_PASSWORD` (and `STRATO_PORT` if not 22);
- variables `STRATO_REMOTE_PATH` (the site's own folder, e.g. `/realhealthkombucha`) and `STRATO_DEPLOY` = `true`.

The webspace can also hold sattva-reset.com, so the script refuses the webspace root and any non-empty folder without its manifest `.rhk-deploy.json`; it uploads only changed files and deletes only files it put there itself. The server's host key must match `tools/strato_known_hosts` (`ssh-keyscan -t ed25519,rsa <host>` if the host ever changes). In STRATO's domain settings, realhealthkombucha.com (and www) point to that folder; MX records stay as they are.

Screenshots all 14 pages at 1440px and 390px into `review/shots/`, writes a gallery `review/index.html` (`review/` is gitignored), checks the 390px pages for horizontal scroll and the header at 960, 1100 and 1261px in both languages (the nav must stay on one row). Exits 1 and lists the problems if a check fails. Needs google-chrome and ImageMagick.

## Phase 2 (go live on realhealthkombucha.com)
1. Add a deploy step that uploads `output/` to STRATO over SFTP, with host/user/password stored as GitHub repository secrets (never in the repo).
2. Set `CONTENT["preview"] = False` in `src/content.py` (removes noindex, allows robots, adds the sitemap to `robots.txt`).
3. DNS in the STRATO panel: change the `www` CNAME (currently `sites.framer.app`) and the apex A record (currently `52.223.52.2`) to the new hosting. Do NOT change the MX record `smtpin.rzone.de`.
4. Keep Framer until the new site is confirmed live.

There is no contact form any more, so no PHP mail script needs hosting: the Contact page offers WhatsApp, Instagram, email and phone, and orders go through the orders app, WhatsApp or a pre-filled email.
